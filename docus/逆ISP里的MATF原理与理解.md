# 逆 ISP 里的 MATF：原理、数学形式、为何“不可逆”、以及如何建模

> 说明：不同厂商/团队对缩写不完全统一。你提到的 **MATF** 在 ISP/计算摄影语境里最常见的含义是：  
> **M**otion **A**daptive **T**emporal **F**ilter / **F**usion（运动自适应时域滤波/融合）  
> ——属于 **TNR（Temporal Noise Reduction）/ MFNR（Multi-Frame Noise Reduction）/ MCTF** 这一类“跨帧降噪”模块。
>
> 这类模块经常是你在视频里看到 **鬼影/拖影** 的第一嫌疑人：只要运动判定或遮挡处理失误，历史帧就会被错误混入当前帧。

---

## 1. MATF 在 ISP 里到底做什么？

### 1.1 目标：用“时间维”换 SNR（信噪比）
单帧噪声（尤其低照度）很强，但噪声在帧间往往近似独立；如果能把多帧在同一位置的像素做平均，噪声方差会下降：

- **静止区域**：多帧平均非常有效（噪声 \(\sigma\) 约按 \(\frac{1}{\sqrt{N}}\) 下降）。
- **运动区域**：不能直接平均，否则会把“上一帧的物体”混到当前帧 → **鬼影**。

于是 MATF 的核心就是：
- **尽可能在静止区域做强融合**（降噪）
- **在运动/遮挡区域减少或禁止融合**（避免鬼影）

### 1.2 它通常位于哪里？
不同 ISP 管线差异很大，但典型规律是：
- **时域降噪/融合**通常发生在 RAW 域（更接近物理噪声）或 demosaic 后的线性域 / YUV 域
- 可能对 **Y（亮度）** 和 **CbCr（色度）** 使用不同强度（色度更容易平滑）

---

## 2. “Motion-Adaptive” 的本质：给每个像素一个时间融合权重

把它理解成“每个像素、每个时刻的自适应低通滤波器”最直观。

### 2.1 最简形式：一阶 IIR（递推）时域滤波
这是很多实时 TNR 的基本骨架：

\[
O_t(x) = \alpha_t(x)\, I_t(x) + (1-\alpha_t(x))\, O_{t-1}(x)
\]

- \(I_t(x)\)：当前帧输入（可能是 RAW/线性 RGB/YUV 的某一级信号）
- \(O_t(x)\)：MATF 输出（给后续 ISP 或编码）
- \(\alpha_t(x)\in[0,1]\)：**融合系数 / 更新系数**
  - \(\alpha\) 大：更信任当前帧（更少历史）→ 更少鬼影，但噪声更大
  - \(\alpha\) 小：更信任历史（更强融合）→ 更强降噪，但更易拖影

### 2.2 \(\alpha_t(x)\) 怎么来的？
“运动自适应”意味着 \(\alpha_t(x)\) 不固定，而由一堆信号决定，常见包括：

- **motion strength / similarity**：当前帧与参考帧（或历史输出）差异越大，越不融合  
  例如：
  \[
  d_t(x)=|I_t(x)-\hat I_{t-1}(x)|
  \Rightarrow \alpha_t(x)=\text{clip}(k\cdot d_t(x), 0, 1)
  \]
- **noise level / ISO**：噪声越大，越想融合（降低 \(\alpha\)）
- **detail/edge**：边缘处更谨慎（避免边缘拖尾）
- **occlusion/confidence**：对齐（warp）不可靠时，提高 \(\alpha\)

> 注：很多实现会用 LUT、分段函数、或多级 mask（静止/轻动/强动）来生成权重，工程上比“纯公式”更常见。

## 3. 从 MATF 到 “多帧融合”版本（更接近 MFNR/MCTF）

如果你的管线是多帧融合（而不是简单递推），形式更像：

\[
O_t(x)=\frac{\sum_{i=0}^{K} w_i(x)\, I_{t-i}(W_i(x))}{\sum_{i=0}^{K} w_i(x)+\epsilon}
\]

- \(W_i(x)\)：把历史帧对齐到当前帧坐标的 warp（光流/块匹配/特征匹配）
- \(w_i(x)\)：像素级权重（运动、遮挡、噪声、细节、曝光变化…综合而来）

### 3.1 为什么视频里“深红/高饱和”更容易出鬼影？
经验上，高饱和（尤其红）区域更容易触发误判，常见原因：
- **色度通道更易 clip/量化**（CbCr/R 通道极值多），导致帧间差异度量失真  
- 对齐/相似度若主要在 **Y（亮度）** 上算，红衣服这种“色度变化大、亮度变化不大”的区域会被误认为“静止可融合”
- 运动 mask 在强噪声/强压缩下不稳定，权重在帧间跳动 → 看起来像“残影闪烁”

## 4. 为什么说 MATF 在“逆 ISP”里很难（甚至不可能）严格求逆？

### 4.1 MATF 本质是“信息丢失”的平滑
无论递推还是多帧平均，本质都是在时间维做低通，丢掉了“高频变化”：
- 噪声被压下去了（你想要）
- 但真实细节的快速变化也被压了（你不想要）

因此从 \(O_t\) 想严格恢复 \(I_t\) 是不适定问题：很多不同的 \(I_t\) 都能产生相同的 \(O_t\)。

### 4.2 递推形式还引入“状态”
IIR 形式里 \(O_t\) 依赖 \(O_{t-1}\)，系统带记忆；这意味着：
- 你只看某一帧的输出，很难知道它混入了多少历史信息
- 历史里发生过什么（遮挡、运动误判）会“污染”后续帧

这也是为什么实际工程里“鬼影”常呈现为拖尾：状态把错误带到了后面。

## 5. 在“逆 ISP / 数据退化”里如何处理 MATF？（三种常见目标）

这里的关键是先搞清楚你做逆 ISP 的目的是什么：

### 5.1 目标 A：合成训练数据，让模型适配真实视频链路
如果你要训练/评测一个会在真实相机视频管线上运行的模型，那么合成退化时就应该把 MATF 的影响纳入进去（否则域差距很大）。

- **做法 1（推荐）**：在合成 RAW 噪声后，显式模拟一个“简化 MATF”
  - 静止区域：强融合
  - 运动区域：弱融合或不融合
  - 加一个很粗的块匹配/光流来近似对齐
- **做法 2（更工程）**：用真实 ISP 输出的视频作为 teacher，做蒸馏/对齐训练（绕开显式建模）

### 5.2 目标 B：从 sRGB“还原”到类 RAW（像 `unprocessing.py` 那样）
你当前仓库的 `unprocessing.py` 是 **单帧逆 ISP**，它不包含时间域模块（也就不会出现 MATF）。

如果你硬要把 MATF 也塞进这个逆过程，要注意：
- MATF 是正向 ISP 的视频模块；单帧 sRGB 本身就不携带“时间维信息”
- 你能做的只有：在生成“退化序列”时，把时间相关性模拟出来（例如让噪声跨帧相关、或引入轻微拖尾）

### 5.3 目标 C：解释/定位鬼影问题（最实用）
把 MATF 当成一个“带权重的时间混合器”，你只需要盯住两张图：
- **motion mask / weight map**：哪里在用历史、用了多少
- **warping / alignment 结果**：历史帧对齐到当前帧是否错位

只要这两者在红衣服附近出错，就会出现你描述的“快递小哥背后鬼影”。

## 6. 一个可落地的“简化 MATF”伪代码（帮助你建立直觉）

下面用 IIR 形式举例（容易实现，也足够解释鬼影）：

```python
def matf_iir(curr, prev_out, motion, alpha_static=0.05, alpha_moving=0.8):
    """
    简化 MATF（IIR）：
    - curr: 当前帧图像 (H,W,C) float
    - prev_out: 上一帧输出 (H,W,C)
    - motion: 运动强度 (H,W) in [0,1]，1=强运动
    """
    # motion 越大 → alpha 越大（更信任当前帧）
    alpha = alpha_static * (1 - motion) + alpha_moving * motion
    alpha = alpha[..., None]  # broadcast to channels
    out = alpha * curr + (1 - alpha) * prev_out
    return out
```

这段代码里：
- 如果 motion 估计把红衣服附近误判为“静止”（motion≈0），就会用很小的 alpha → 历史混入很重 → **鬼影**。
- 如果量化/压缩让 motion 在帧间抖动，alpha 也抖动 → 你看到的鬼影会“闪”。

## 7. 和你正在做的“逆 ISP + 量化伪影分析”怎么串起来？

你之前提到的高饱和鬼影，在工程上经常是：
- **MATF/TNR 的 motion mask 不鲁棒**（根因）
- **量化（W16A8）/clip/色度处理不一致**让 mask 更容易误判（放大器）

因此排查优先级通常是：
- 先确认：链路里是否存在 MATF/TNR/MCTF/MFNR（视频基本都会有）
- 再对比：FP16 vs 量化后，motion mask / weight map 在高饱和区域的变化

---

## 8. 你可以用一句话“理解 MATF”

**MATF = 在时间维做降噪的自适应滤波器：静止区域尽量用历史帧平均，运动区域尽量只用当前帧；运动判定一旦出错，就会产生鬼影。**
